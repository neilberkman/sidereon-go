## C ABI ownership, errors, and copying evidence

- sidereon.h:7-19 lists constructor/out-parameter ownership, matching _free functions, NULL-safe free, and the general read-only-shareable handle statement.
- sidereon.h:21-28 states OK is the only success, failures write thread-local last-error text, status_message maps fixed names, outputs are initialized/cleared before validation, and failed calls transfer no new handle.
- sidereon.h:29-33 defines variable output query semantics: NULL plus length zero asks for required count; too-small buffers return INVALID_ARGUMENT, write zero, and report required count.
- sidereon.h:173-215 defines the eight status values: OK, NULL_POINTER, INVALID_ARGUMENT, INVALID_TOKEN, SP3_PARSE, SOLVE, PANIC, TIMEOUT.
- ../../repos/sidereon-c/bindings/c/src/lib.rs:416-445 implements thread-local LAST_ERROR and set_last_error; lib.rs:458-468 wraps the FFI boundary with panic capture.
- lib.rs:739-754 validates raw input slices and creates borrowed views only for the duration of a call; lib.rs:799-803 implements NULL-safe boxed free; lib.rs:847-867 copies variable output vectors into caller buffers.
- The Go plan therefore uses typed StatusError{Status, Message}, same-OS-thread error capture, explicit Close plus runtime.AddCleanup backstop for owning handles, and temporary C-owned copies for every input slice/array.

## Parity assessment method

1. Treat every top-level .pyi class and def plus the package __all__ inventory as public/documented, including auxiliary modules. Do not treat private underscore modules as an additional public surface.
2. Group overloads, properties, enums, aliases, dataclasses, codecs, and transport conveniences by capability. Numeric and protocol capabilities are matched to exact C name families; pure Go transport/presentation capabilities are mapped to Go-owned APIs.
3. Search the committed header for corresponding sidereon_* families and inspect the C module declarations. The matrix records the relevant Python line range, C family, planned Go package/signature, ownership, and gate result.
4. A hard STOP requires a documented Python numeric/protocol capability with no C expression and no permitted Go-owned transport/presentation decomposition. The 11 capabilities above meet that test. NTRIP sockets, filesystem, HTTP, decompression, cache locks, paths, formatting, and aliases remain explicitly Go-owned conveniences under the task requirements, but they do not cure these gaps.

## Ambiguities for independent supervisor review

- Per-handle concurrency: sidereon.h provides one general statement but no complete per-type or per-operation synchronization matrix. Confirm whether any mutable C handles internally synchronize; until then Go should serialize all mutation and Close.
- Read-vs-Close races: the header does not define them beyond saying concurrent free invalidates handles/borrowed pointers. The Go API must reject use after Close and avoid concurrent Close.
- Thread-local error retrieval across cgo calls: sidereon_last_error_message is a separate C entry point. Confirm the implementation will keep the fallible call and message read on one OS thread (for example, runtime.LockOSThread around the pair).
- Python inventory semantics: .pyi declarations and __all__ are the documented baseline, but aliases/re-exports and runtime-only behavior can make simple declaration counts non-deduplicated. The matrix explicitly includes transport/presentation families rather than pretending they are C numeric functions.
- The auxiliary stubs total 81 class declarations, not 84; the 62 function declarations are exact. Review whether the supervisor wants class counts deduplicated across re-exports.
- The complete C table uses header line numbers and names extracted from the generated header; multiline parameter types remain in the authoritative header rather than being copied into a second error-prone transcription.
- The staticlib evidence is manifest/README evidence at the public tag. The worker did not build or copy the archive because this deliverable is an audit and must not add implementation artifacts.
- Domain totals are a deterministic lexical grouping for planning, not a statement about Rust module ownership. Review any symbol whose full name contains multiple domain tokens, especially solve, signal, static, exact, and terrain.
